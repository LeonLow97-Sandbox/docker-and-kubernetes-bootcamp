# Question 1: Multi-Container Pods & Shared Volumes

**Context**

A developer needs to deploy a Pod where a **sidecar container** generates data that the **main application container** serves.

**Task**

Create a Pod named `busybox-logger` in the `default` namespace.

**Requirements**

- **Main container**
  - Name: `web-container`
  - Image: `nginx`
  - Mount path: `/usr/share/nginx/html`

- **Sidecar container**
  - Name: `sidecar-container`
  - Image: `busybox`
  - Command: `/bin/sh`, `-c`, `while true; do date >> /var/log/index.html; sleep 5; done`
  - Mount path: `/var/log`

- **Storage**
  - Use an `emptyDir` volume named `shared-data` so both containers can access the same `index.html` file.
  - Ensure the `sidecar-container` writes to the same file that `nginx` serves.

**Validation**

Once the Pod is running, verify that the following command returns a list of dates generated by the sidecar:

```sh
kubectl exec busybox-logger -c web-container -- curl localhost
```

<details>
<summary>My Answer</summary>

1. `k run busybox-logger --image=nginx $do > pod.yaml`
2. `vim pod.yaml`

```yaml
apiVersion: v1
kind: Pod
metadata:
  creationTimestamp: null
  labels:
    run: busybox-logger
  name: busybox-logger
spec:
  containers:
    - image: nginx
      name: web-container
      resources: {}
      volumeMounts:
        - name: shared-data
          mountPath: /usr/share/nginx/html
    - image: busybox
      name: sidecar-container
      command:
        [
          "sh",
          "-c",
          "while true; do date >> /var/log/index.html; sleep 5; done",
        ]
      volumeMounts:
        - name: shared-data
          mountPath: /var/log
  dnsPolicy: ClusterFirst
  restartPolicy: Always
  volumes:
    - name: shared-data
      emptyDir: {}
status: {}
```

3. `k get pods -w`
4. `k exec busybox-logger -c web-container -- curl localhost:80`

</details>

# Question 4: Services & NetworkPolicies

A team needs to secure communication between tiers in a cluster by isolating backend Pods so they only accept traffic from designated frontend Pods.

Perform the following setup in the `secure-net` namespace. **Create the namespace if it does not exist.**

- **Frontend Deployment**
  - Name: `frontend`
  - Namespace: `secure-net`
  - Image: `nginx:1.25`
  - Replicas: `1`
  - Pod labels: `app=frontend`

- **Backend Deployment**
  - Name: `backend`
  - Namespace: `secure-net`
  - Image: `redis:7-alpine`
  - Replicas: `1`
  - Pod labels: `app=backend`
  - Container port: `6379`

- **Service**
  - Name: `backend-svc`
  - Namespace: `secure-net`
  - Type: `ClusterIP`
  - Port: `6379`
  - Target port: `6379`
  - Selector: `app=backend`

- **NetworkPolicy**
  - Name: `allow-frontend-to-backend`
  - Namespace: `secure-net`
  - Pod selector: `app=backend`
  - Policy type: `Ingress`
  - Allow ingress **only from Pods labeled `app=frontend`** on TCP port `6379`.

Verify that the `NetworkPolicy` restricts inbound traffic to the backend on port `6379` to **frontend Pods only**.

<details>
<summary>My Answer</summary>

1. `k create deploy frontend -n secure-net --image=nginx:1.25 --replicas=1 $do > fe-deploy.yaml`
2. `k create deploy backend -n secure-net --image=redis:7-alpine --replicas=1 --port=6379 $do > be-deploy.yaml`
3. `k expose deploy backend --name=backend-svc -n secure-net --type=ClusterIP --port=6379 --target-port=6379 $do > svc.yaml`
4. `k create -f svc.yaml -f fe-deploy.yaml -f be-deploy.yaml`
5. `vim netpol.yaml`

```yaml
kind: NetworkPolicy
metadata:
  name: allow-frontend-to-backend
  namespace: secure-net
spec:
  podSelector:
    matchLabels:
      app: backend
  policyTypes:
    - Ingress
  ingress:
    - from:
        - podSelector:
            matchLabels:
              app: frontend
      ports:
        - protocol: TCP
          port: 6379
```

6. `k create -f netpol.yaml`
7. Verify

```sh
k run test-frontend \
--image=busybox:1.36 \
--labels=app=frontend \
--restart=Never \
--rm -it \
-- nc -vz -w 2 backend-svc 6379
```

</details>

An application requires traffic routing based on HTTP paths so that incoming requests are directed to different backend microservices through an `Ingress` controller.

Perform the following setup in the `ingress-space` namespace. **Create the namespace if it does not exist.**

- **Video Application**
  - Deployment name: `video-deployment`
  - Image: `nginx:1.25`
  - Replicas: `1`
  - Service name: `video-svc`
  - Service type: `ClusterIP`
  - Port: `80`
  - Target port: `80`

- **Store Application**
  - Deployment name: `store-deployment`
  - Image: `nginx:1.25`
  - Replicas: `1`
  - Service name: `store-svc`
  - Service type: `ClusterIP`
  - Port: `80`
  - Target port: `80`

- **Ingress**
  - Name: `app-ingress`
  - Namespace: `ingress-space`
  - Ingress class name: `nginx`
  - Route path prefix `/video` to `video-svc` on port `80`.
  - Route path prefix `/store` to `store-svc` on port `80`.
  - Use `PathType: Prefix` for **both paths**.

Verify that the `Ingress` routes:

- `/video` → `video-svc:80`
- `/store` → `store-svc:80`

<details>
<summary>My Answer</summary>

1. `k create ns ingress-space`
2. `kns ingress-space`
3. `k create deploy video-deployment --image=nginx:1.25 --replicas=1 -n ingress-space`
4. `k expose deploy video-deployment -n ingress-space --name=video-svc --type=ClusterIP --port=80 --target-port=80`
5. `k create deploy store-deployment -n ingress-space --image=nginx:1.25 --replicas=1`
6. `k expose deploy store-deployment -n ingress-space --name=store-svc --type=ClusterIP --port=80 --target-port=80`
7. `k create ingress app-ingress -n ingress-space --rule=/video=video-svc:80 --rule=/store=store-svc:80 --class=nginx $do > ingress.yaml`
8. `vim ingress.yaml`

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  creationTimestamp: null
  name: app-ingress
  namespace: ingress-space
spec:
  ingressClassName: nginx
  rules:
    - http:
        paths:
          - backend:
              service:
                name: video-svc
                port:
                  number: 80
            path: /video
            pathType: Prefix
          - backend:
              service:
                name: store-svc
                port:
                  number: 80
            path: /store
            pathType: Prefix
status:
  loadBalancer: {}
```

9. `k create -f ingress.yaml`

## The 3 Valid Combinations

| **Combination**                      | **Target Resources Allowed**                                       | **Scope / Where It Works**                    |
| ------------------------------------ | ------------------------------------------------------------------ | --------------------------------------------- |
| **Role + RoleBinding**               | Namespaced resources only (e.g., Pods)                             | **1 Namespace only**                          |

A development team needs to containerize a lightweight script application and build an OCI/Docker container image locally on the node before deploying it to Kubernetes.

Create a Dockerfile and build a container image according to the specification below in the directory `/tmp/app-build`. **Create the directory if it does not exist.**

- **Directory Setup**
  - Working directory: `/tmp/app-build`
  - Create a script named `entrypoint.sh` inside `/tmp/app-build` with the following content:

```sh
#!/bin/sh
echo "Application running..."
```

- Ensure `entrypoint.sh` is executable:

```sh
chmod +x /tmp/app-build/entrypoint.sh
```

- **Dockerfile**
  - Create a file named `/tmp/app-build/Dockerfile`.
  - Base image: `alpine:3.19`
  - Set the working directory to `/app`.
  - Copy `entrypoint.sh` into `/app/entrypoint.sh`.
  - Set the default command/entrypoint to execute `/app/entrypoint.sh`.

- **Image Build**
  - Build the container image using `docker build` or `podman build` from `/tmp/app-build`.
  - Tag the resulting image as `custom-app:1.0`.

Verify that the built image exists using:

```sh
docker images custom-app:1.0
```

or:

```sh
podman images custom-app:1.0
```

<details>
<summary>My Answer</summary>

1. `mkdir -p /tmp/app-build`
2. `vim /tmp/app-build/entrypoint.sh`

```sh
#!/bin/sh
echo "Application running..."
```

3. `chmod +x /tmp/app-build/entrypoint.sh`
4. `vim /tmp/app-build/Dockerfile`

```Dockerfile
FROM alpine:3.19

WORKDIR /app

COPY entrypoint.sh /app/entrypoint.sh

ENTRYPOINT ["./entrypoint.sh"]
```

5. `podman build -t custom-app:1.0 /tmp/app-build`
6. `docker images custom-app:1.0`

```
REPOSITORY             TAG       IMAGE ID       CREATED         SIZE
localhost/custom-app   1.0       498ddb8a754f   5 minutes ago   8.03MB
```

</details>

# Question 19: Helm Chart Release Management

Helm is heavily tested in the CKAD exam (Application Deployment domain). You are tasked with installing, modifying parameters, and upgrading a Helm release in a specific namespace.

- **Namespace**
  - Create a namespace named `helm-space`.

- **Helm Repository**
  - Add the Bitnami repository: `https://charts.bitnami.com/bitnami`
  - Update local Helm repositories.

- **Install a Helm Release**
  - Release name: `my-web-app`
  - Install the `apache` chart from the Bitnami repository into `helm-space`.
  - Set `replicaCount` to `2`.
  - Set `service.type` to `ClusterIP`.

- **Upgrade the Release**
  - Upgrade `my-web-app` in `helm-space`.
  - Update `replicaCount` to `3`.
  - Preserve existing values using `--reuse-values`.

Confirm that:

- The Helm release `my-web-app` is present in `helm-space`.
- The Deployment under `my-web-app` has scaled to `3` replicas.

<details>
<summary>My Answer</summary>

1. `helm repo add bitnami https://charts.bitnami.com/bitnami`
2. `helm repo update bitnami`
3. `helm install my-web-app bitnami/apache --set=replicaCount=2,service.type=ClusterIP --create-namespace --namespace=helm-space`
4. `helm upgrade my-web-app bitnami/apache --set=replicaCount=3 --reuse-values --namespace=helm-space`
5. `helm list --namespace=helm-space`

```
NAME            NAMESPACE       REVISION        UPDATED                                  STATUS          CHART           APP VERSION
my-web-app      helm-space      2               2026-08-22 22:28:40.210843 +0800 +08     deployed        apache-11.4.29  2.4.65
```

6. `k get deploy -n helm-space`

```
NAME                READY   UP-TO-DATE   AVAILABLE   AGE
my-web-app-apache   0/3     3            0           104s
```

</details>

# Question 20: Kustomize Overlay Management

Kustomize is a built-in configuration management tool in `kubectl` (`kubectl apply -k`). On the CKAD exam, you may be asked to create base resources and an environment overlay that modifies labels, replicas, or image tags.

- **Directory Structure**
  - Create a base directory: `/tmp/kustomize/base`
  - Create a dev overlay directory: `/tmp/kustomize/overlays/dev`

- **Base Configuration**
  - Create a Deployment manifest named `deployment.yaml` with:
    - Deployment name: `app-deploy`
    - Replicas: `1`
    - Container name: `app-container`
    - Image: `nginx:1.24`
    - Container port: `80`
  - Create a `kustomization.yaml` inside `/tmp/kustomize/base` that references `deployment.yaml`.

- **Dev Overlay Configuration**
  - Create a `kustomization.yaml` inside `/tmp/kustomize/overlays/dev` that references the base directory.
  - Set `namePrefix` to `dev-` so the Deployment becomes `dev-app-deploy`.
  - Update the image from `nginx:1.24` to `nginx:1.25`.
  - Add the label `env=development`.
  - Increase replicas to `3`.

Apply the dev overlay and verify that:

- The Deployment is named `dev-app-deploy`.
- The Deployment has `3` replicas.
- The container uses image `nginx:1.25`.
- The label `env=development` is applied.

<details>
<summary>My Answer</summary>

1. `mkdir -p /tmp/kustomize/base`
2. `mkdir -p /tmp/kustomize/overlays/dev`
3. `k create deploy app-deploy --replicas=1 --image=
nginx:1.24 --port=80 --dry-run=client -o yaml > /tmp/kustomize/base/deployment.yaml`
4. `vim /tmp/kustomize/base/deployment.yaml`

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  creationTimestamp: null
  labels:
    app: app-deploy
  name: app-deploy
spec:
  replicas: 1
  selector:
    matchLabels:
      app: app-deploy
  strategy: {}
  template:
    metadata:
      creationTimestamp: null
      labels:
        app: app-deploy
    spec:
      containers:
        - image: nginx:1.24
          name: app-container
          ports:
            - containerPort: 80
          resources: {}
status: {}
```

5. `vim /tmp/kustomize/base/kustomization.yaml`

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

resources:
  - deployment.yaml
```

6. `vim /tmp/kustomize/overlays/dev/kustomization.yaml`

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

resources:
  - ../../base

namePrefix: dev-

images:
  - name: nginx
    newName: nginx
    newTag: "1.25"

labels:
  - pairs:
      env: development

replicas:
  - name: app-deploy
    count: 3
```

7. `k apply -k /tmp/kustomize/overlays/dev/kustomization.yaml`

</details>
